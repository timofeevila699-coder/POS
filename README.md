# ПОС — преподавательская оценка студентов

Учебное консольное приложение на C# / .NET 8. Один курс, одна ведомость, локальное хранение в JSON. Без базы данных и веб-интерфейса.

## Запуск

Нужен **.NET SDK 8 или более новый**. Открыть терминал в папке с `Pos.sln`:

```sh
dotnet restore
dotnet build --no-restore
dotnet run --project src/Pos.Console
```

В Visual Studio 2022 с поддержкой .NET 8 открыть `Pos.sln`, выбрать `Pos.Console` стартовым проектом.

```sh
# Сквозной сценарий с готовыми данными и CSV-экспортом
dotnet run --project src/Pos.Console -- --demo

# Альтернативная стратегия (все критерии равнозначны)
dotnet run --project src/Pos.Console -- --demo --equal

# Проверки
dotnet test
```

Данные обычного запуска сохраняются в `data/gradebook.json`, демо — в `data/demo.json`. Пути считаются от текущей рабочей папки. Демо можно повторять; основную ведомость оно не меняет. Полученный CSV находится в `demo-results.csv`. Приложение рассчитано на один запущенный процесс.

## Что можно сделать

- Добавить студента, вывести список студентов.
- Добавить критерий с названием, максимумом и весом, вывести рубрикатор.
- Выставить или исправить оценку, добавить комментарий, посмотреть и отменить оценку.
- Посчитать итоги, средний результат, минимум и максимум, вывести студентов по убыванию результата.
- Экспортировать подробную ведомость в CSV с разделителем `;` и UTF-8 BOM для Excel: студент, критерий, балл, максимум, вес, комментарий и общий итог из 10. Каждому критерию студента соответствует отдельная строка. Пропуск отмечается как «Не выставлена», настоящий нулевой балл — как `0`. Общий итог повторяется в строках студента, складывать эти значения не нужно.

Повторное выставление оценки той же паре «студент + критерий» исправляет её. Имена студентов могут совпадать: идентичность определяется `Guid`. Названия критериев в одной ведомости уникальны без учёта регистра. Редактирование и удаление самих студентов и критериев не добавлялись: по ТЗ они необязательны. Импорт тоже не входит в обязательные сценарии.

Балл проверяется сразу после ввода, до запроса комментария. При выходе за диапазон консоль показывает ошибку и возвращает меню, прежняя оценка остаётся. Предварительная проверка использует ту же доменную фабрику, что и сохранение: правило диапазона не дублируется в UI.

## Правило расчёта

По умолчанию:

`Итог = 10 × сумма((балл / максимум критерия) × (вес / сумма весов))`.

Веса положительные, их сумма не обязана быть равна 1 или 100. Пропущенная оценка считается нулём, но вес критерия остаётся в знаменателе. Без критериев итог равен нулю. Эти правила выбраны явно, поскольку в ТЗ они не заданы. Итог округляется до двух знаков (`AwayFromZero`), хранить его отдельно не нужно. После изменения оценки или добавления критерия итог автоматически считается по актуальной ведомости.

Пример демо: ДЗ — максимум 20, вес 40; экзамен — максимум 10, вес 60.

- Анна: ДЗ 16, экзамен 9 → `10 × (16/20 × 0,4 + 9/10 × 0,6) = 8,60`.
- Иван: ДЗ 10, экзамен 6 → `5,60`.
- Средний итог — `7,10`.

При `--equal` веса из рубрикатора не используются: берётся среднее нормированных оценок. Результаты демо — `8,50` и `5,50`. Это способ сравнить два правила, а не правило по умолчанию.

## DDD

| Понятие | Реализация и причина |
| --- | --- |
| Ubiquitous Language | `Student` — студент, `Criterion` — критерий, `Evaluation` — оценка, `Gradebook` — ведомость, `FinalScore` — итог |
| Entity | `Student` и `Criterion` имеют устойчивый `Id`; `Evaluation` определяется парой `StudentId + CriterionId`, для которой допускается одна текущая оценка |
| Value Object | `Score` — неизменяемый `record struct`, сравнивается по значению, запрещает отрицательные числа. Например, два `new Score(5)` равны |
| Агрегат | `Gradebook` — корень ведомости одного курса. Внутри студенты, рубрикатор и оценки. Такая граница позволяет проверять принадлежность критерия и студента без распределённых операций |
| Инварианты | Имена не пустые, максимум и вес положительные, балл от 0 до максимума, студент и критерий присутствуют в ведомости, одна оценка на пару |
| Repository | `IGradebookRepository` — порт Application; JSON-реализация находится в Infrastructure |
| Domain Service | `FinalScoreService` считает итог по рубрикатору и оценкам с помощью стратегии |

Сущности не имеют публичных сеттеров. Коллекции доступны через read-only обёртки. Фабрика проверяет связи и диапазон до создания оценки. При неудачной корректировке старая оценка сохраняется. JSON восстанавливается через те же доменные методы, а не в обход проверок. DTO для JSON находятся только в адаптере.

## Архитектура: облегчённая Ports and Adapters

```text
Pos.Console ──→ Pos.Infrastructure ──→ Pos.Application ──→ Pos.Domain
    │                 │                      │
    └─────────────────┴──────────────────────→ Domain (типы модели)
```

Стрелки показывают зависимости проектов; зависимости транзитивны. Domain не ссылается ни на один другой проект и не знает о консоли, JSON, CSV или DI.

- `src/Pos.Domain` — сущности, VO, агрегат, фабрика, стратегии, доменный сервис.
- `src/Pos.Application` — сценарии (`PosFacade`), порты репозитория и экспорта, строка отчёта.
- `src/Pos.Infrastructure` — выходные адаптеры: JSON-хранилище, CSV-экспорт.
- `src/Pos.Console` — входной адаптер (меню) и composition root (`Program.cs`).
- `tests/Pos.Tests` — xUnit-тесты модели и адаптеров.

`Microsoft.Extensions.DependencyInjection` собирает граф в `Program.cs`. Там выбираются стратегия, путь хранения и реализации портов. Консоль использует фасад, фасад зависит от портов и домена. Файл сначала записывается во временный JSON, затем заменяет основной. Если сохранение не удалось, фасад заново загружает сохранённое состояние.

## Паттерны

Используется по одному паттерну из каждой требуемой группы.

| Группа | Паттерн и место | Для чего |
| --- | --- | --- |
| Порождающий | Фабрика, `EvaluationFactory` | Единая точка создания оценки: проверяет наличие студента и критерия и допустимость балла. Используется и при вводе, и при восстановлении JSON |
| Структурный | Facade, `PosFacade` | Даёт консоли готовые операции, скрывает работу с репозиторием, расчётом и экспортом |
| Поведенческий | Strategy, `IFinalScoreStrategy` | Позволяет заменить взвешенный расчёт на равные веса без изменения `FinalScoreService` и UI |

Фабрика здесь — простая фабрика, как в примере задания, а не иерархия GoF Factory Method. Наследование ради единственной разновидности оценки не вводилось. Repository и DI описаны отдельно: это не дополнительные GoF-паттерны.

## Проверки и ограничения

Тесты проверяют диапазон и границы баллов, чужой критерий и неизвестного студента, валидность критерия и имени, дубликаты, равенство VO, нормализацию максимумов и весов, пропуски, исправление/отмену, отсутствие влияния чужих оценок, JSON round-trip и экранирование CSV.

Исходная версия проверена на .NET SDK 8.0.100: оба демо-режима и сценарий через меню (дробный балл, исправление, экспорт, повторный запуск и отмена). После исправлений добавлены регрессионные тесты: ошибка до запроса комментария, сохранение прежнего балла, подробный экспорт, различие пропуска и нуля, обновление CSV после исправления и отмены. В `examples` лежат вывод взвешенного демо и его CSV.

Обычные ошибки ввода выводятся в консоль без завершения программы. При повреждении JSON запуск завершается с сообщением: файл следует исправить или убрать, сохранив его копию. Импорт произвольного JSON, несколько курсов, пересдачи, апелляции и одновременная работа нескольких процессов не реализованы. Числа можно вводить с точкой или запятой.
